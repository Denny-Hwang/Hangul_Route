# Phase 3 — Stage 2–7 학습 과정 (WO-19 – WO-27)

먼저 `README.md` 를 읽는다. 이 Phase 는 대부분 콘텐츠 작업이다. 콘텐츠를 쓰는 세션은 `.claude/skills/content-skill/SKILL.md`, `docs/workflows/new-content.md`, `docs/workflows/story-content-qa.md` 를 따른다.

실제 분량(리뷰에서 확인): 상위 단계 50셀·153퀘스트·약 12시간, 누적 고유 어절 약 900. 어휘 토픽 12 × 12 = 144개. 이야기 35편(한국어 문장 총 210개). 배치 문항 261개. Stage 5 는 `content/episodes/` 에 폴더가 없고 `apps/mobile/src/content/books.ts` 의 책 10권이 `content/stories` 를 `read` 단계로 재사용한다.

콘텐츠 위치: `content/episodes/stage-{2,3,4,6,7}/<theme>.json` 과 `<theme>.v2.json`, 빌드 `scripts/build-lessons.mjs`, 검증 `packages/content-schema/src/lesson-lint*.ts`, 사양 `docs/specs/F-CURR-001-upper-stage-content.md`.

깨면 안 되는 것(F-CURR-001 §3.1, 테스트로 강제됨): 퀘스트당 새 항목 1문형·4단어 이하, "한 번 가르치고 여러 번 묻기", 절반 이상 재사용, 채점되는 읽기는 배운 자모만.

**사람 검수.** 이 Phase 에서 한국어 문장을 새로 쓰거나 고치는 모든 PR 은 머지 전에 WO-27 의 검수자(또는 오너)가 본다. 모델 검토만으로 학습자에게 내보내지 않는다.

**예상.** 사양 0.5d, 수정 1d, 클립 별도.

## WO-21 문법을 묻는 사람에게 이유를 알려준다

**목표.** 아이는 덩어리로 배우고, 이유를 알고 싶은 사람(주로 성인)은 한 번 탭으로 규칙을 본다. 말투 설명이 표시되지 않고 빠지는 일을 없앤다.

**근거.**
- 보고: Discover 의 `noteEn` 은 이형태 규칙 수준("Use 이 after a final consonant, 가 after a vowel").
- 보고: `quest:stage2-life-v2-q1` 에서 달다·짜다·맵다를 가르치고 `quest:stage3-life-v2-q1` 에서 달아요·매워요가 설명 없이 나온다. ㅂ 불규칙(매워요·더워요·추워요·귀여워요)과 으 탈락(써요·커요·예뻐요)은 통암기.
- 보고: 은/는 은 Stage 3 부터 `저는`, `오늘은` 으로 노출되고 명시 설명은 Stage 7 의 한 줄. 이/가 와의 대비 없음.
- 보고: 말투·`저/나` 설명은 `culture[]` 의 language 노트에만 있고, `scripts/build-lessons.mjs` 의 `questNotes` 가 보상 단계 "Did you know?" 에 퀘스트당 1개만(문화 노트 우선) 붙인다. `stage3-letters` 는 노트 4개·퀘스트 3개라 n4(저 vs 나)가 표시되지 않는다.

**사양.** `docs/specs/F-CURR-003-why-cards.md` (새 기능: Discover 의 접힌 설명 카드).

| 행 | 모델 | 내용 |
|---|---|---|
| WY-0 | Opus 5.5 | 사양 + 와이어프레임 `design/wireframes/quest/discover-why.md` |
| WY-0b | Opus 5.5 | 시안 `design/screens/` |
| WY-1 | Sonnet 5.5 | 스키마: Discover 항목에 선택 필드 `why`(짧은 영어 설명 + 예 2개), lint |
| WY-2 | Sonnet 5.5 | Discover UI: 접힌 "Why?" 행(기본 접힘), 펼침 상태는 채점·진도와 무관 |
| WY-3 | Opus 5.5 | 콘텐츠: 아래 목록의 설명 작성 |
| WY-4 | Sonnet 5.5 | `build-lessons.mjs`: language 노트를 첫 등장 Discover 로 옮기고, 표시되지 않는 노트가 생기면 빌드 실패 |

**WY-3 이 써야 할 설명(각 3문장 이내, Pre-A1 영어, 예 2개).**
1. 어간 + 아요/어요 (Stage 3 초반 1회): 먹다 → 먹어요, 가다 → 가요.
2. ㅂ 이 바뀌는 낱말 묶음: 맵다 → 매워요, 덥다 → 더워요, 춥다 → 추워요. "These words change ㅂ to 워."
3. 으 가 빠지는 낱말 묶음: 쓰다 → 써요, 크다 → 커요, 예쁘다 → 예뻐요.
4. 은/는 과 이/가: 처음 나오는 곳에서 "은/는 says what we are talking about. 이/가 says who or what does it." + 대비 예 한 쌍.
5. 을/를, 에/에서: 각 첫 등장.
6. 말투: 해요체가 기본이라는 것, 저/나, 반말은 듣기만.

**설계 제약.** "Why?" 를 펼치지 않아도 퀘스트는 완결된다. 펼친 내용은 새 "항목" 으로 세지 않는다(§3.1 의 부하 규칙과 별개). 6세가 읽지 않아도 되도록 기본 접힘, 라벨은 한 단어.

**WY-4 의 실패 조건.** 셀의 language 노트 수가 표시 슬롯보다 많아 하나라도 표시되지 않으면 빌드가 실패한다. 지금 조용히 빠지는 `stage3-letters` n4 가 이 검사에 걸려야 한다.

**수용 기준.** 달아요·매워요가 처음 나오는 Discover 에 "Why?" 가 있다. 모든 language 노트가 어딘가에 표시된다(빌드 검사).

**하지 말 것.** 문법 용어(irregular, conjugation, topic marker)를 학습자 화면에 쓰지 않는다. 설명을 필수 단계로 만들지 않는다.

**예상.** 사양·시안 1d, 구현 1.5d, 콘텐츠 1d.

## WO-22 Stage 5 를 한국어 읽기로

**목표.** Stage 5 "Story" 의 본체가 학습자가 **읽을 수 있는 한국어** 가 된다. 문화 영어 내레이션은 보조로 남는다.

**근거.**
- 확인: `content/stories/sejong-new-letters.json:16` `"recommendedStage": 1`, `:740` "훈민정음은 백성을 가르치는 바른 소리라는 뜻이에요."
- 보고: read 단계는 영어 내레이션 35–138단어 + 장면당 한국어 1문장. 확인 문제는 키워드 뜻 고르기 70개와 영어 detail 35개로, 한국어 문장 이해를 평가하지 않는다.
- 보고: `recommendedStage` 별 한국어 문장 평균 어절 수가 stage1 3.88, stage2 3.22, stage5 2.72 (역전). 어려운 예: `cheugugi-rain-gauge`(Stage 1) "지금 남아 있는 측우기는 국보예요.", `dano-ssireum`(Stage 2) "우승한 사람을 장사라고 불러요.", `pansori-tales`(Stage 2) "토끼는 간을 육지에 두고 왔다고 해요." 쉬운 예: `gyeonu-jingnyeo`(Stage 5) "견우는 목동이에요."
- 보고: listen 내레이션에 "Royal Secretariat", "inscribed", "Intangible Cultural Heritage" 같은 어휘(UI 의 Pre-A1 원칙과 어긋남).

**사양.** `docs/specs/F-STORY-007-graded-korean-stories.md`. F-STORY-001(스키마), F-STORY-003(확인 문제), `story-lint.ts` 수정 포함.

| 행 | 모델 | 내용 |
|---|---|---|
| GS-0 | Opus 5.5 | 사양: 단계별 허용 문형·어휘 목록의 정의 방식, 미니 이야기 형식, 확인 문제 형식 |
| GS-1 | Sonnet 5.5 | `story-lint`: 한국어 문장이 `recommendedStage` 의 허용 목록 안인지 검사(처음에는 warn + 기준선) |
| GS-2 | Opus 5.5 | 시범 3편: Stage 2–4 어휘·문형만으로 쓴 5–10문장 한국어 미니 이야기 |
| GS-3 | Sonnet 5.5 | 한국어를 읽어야 풀리는 확인 문제 형식 2가지(문장 → 그림, 문장 순서 맞추기) |
| GS-4 | Opus 5.5 | 나머지 7편(책 10권 기준), 기존 35편의 한국어 문장 수준 재조정 |
| GS-5 | Sonnet 5.5 | listen 내레이션의 2–3문장 요약판("Pictures first" 수준) 필드와 표시 |

**GS-0 이 정해야 할 것.**
1. **허용 목록의 원천.** 손으로 쓴 목록이 아니라 빌드 산출물에서 만든다: Stage N 까지의 퀘스트가 가르친 어휘·문형(`scripts/build-lessons.mjs` 가 이미 "신규/재사용" 을 센다)을 누적해 `stage-N-allowed` 를 생성한다.
2. **기지어 비율.** 이야기의 한국어 어절 중 허용 목록 안이 95% 이상, 새 낱말은 편당 3개 이하이고 그림이나 gloss 로 받친다(Nation 의 단계별 읽기 자료 기준).
3. **미니 이야기 형식.** 5–10문장, 한 문장 6어절 이하, 해요체, 관형절·인용·`-(으)ㄹ 때` 없음(가르친 적 없으므로). 장면마다 그림. 문장별 음성. 로마자 표시는 WO-11 의 모드를 따른다.
4. **기존 35편의 처리.** 문화 내레이션은 그대로 listen 단계의 자산이다. read 단계의 "장면당 한국어 1문장" 은 (a) 허용 목록 안으로 다시 쓰거나 (b) `recommendedStage` 를 올린다. 편별로 표로 결정한다.
5. **사실 정확성.** 이야기의 사실과 출처는 `story-sources.ts`, `docs/workflows/story-content-qa.md` 절차를 그대로. 리뷰는 약 15편의 연도·수치를 대조해 오류를 찾지 못했다. 이 품질을 유지한다.

**GS-2 지침.** 전래동화나 일상 장면을 쓴다. 예시 수준: "토끼가 있어요. 토끼는 산에 살아요. 거북이가 와요. 거북이는 토끼를 봐요. …" 각 편에 사용 어휘 목록과 허용 목록 대조 결과를 붙인다. WO-27 검수 대상.

**수용 기준.** Stage 5 책의 read 단계에서 한국어 문장 수가 영어 내레이션 문장 수보다 많다. 시범 3편이 lint 를 통과한다. 확인 문제 3개 중 2개 이상이 한국어 문장을 읽어야 풀린다.

**하지 말 것.** 기존 이야기의 사실 서술을 다시 쓰면서 출처 검증을 건너뛰지 않는다. 미니 이야기에 새 문형을 몰래 넣지 않는다.

**예상.** 사양 1d, lint 0.5d, 시범 3편 1.5d, 형식 1d, 나머지 3d, 요약판 1d.
