## 2. User story

> As a teacher, when a learner walks in late, I press one button and the classroom screen shows our class name, the code and a QR code, and nothing else. I press Escape and I am back on my class page.
>
> As a learner, I never see on the classroom screen which letters another learner still needs to practise, and nobody sees mine.

What rows CO-1 and CO-2 do not change: Show the code lives on the class page, so to reach it the teacher opens the class page, and if that page is already on the classroom screen the room sees the roster (names, level pills, minutes, quest counts, with the letters to revisit folded after CO-2) until the button is pressed. OD-CO7 (a) (owner decision 2026-11-24) puts the button on the teacher home, which names no learner, so the roster need never be on the screen.

## 3. Acceptance criteria

### 3.1 The entry: Show the code (row CO-1)

- The class page's action bar (`ClassActionBar`, GX-7 T3) gains **Show the code** (`console.space.codeOverlay.open.cta`), a secondary button that stays in the bar, never under More: after the everyday buttons (Plan, Term plan, Lecture mode, Class report) and before any waiting entry (new devices, class moves). `classActions` (`apps/web/src/lib/console/class-page.ts:36-51`) gains the input `code: boolean` and the action `'showCode'`.
- It is a plain `<button type="button">` styled with `buttonBase` (as `JoinLinkParts.tsx` does), with `aria-haspopup="dialog"` and a ref the page keeps as the opener. The shared `Button` (`components/console/ui.tsx:71`) takes neither a ref nor `aria-haspopup`, and `ui.tsx` is not changed.
- It is shown when `codeOverlayShown(source, now)` is true (new, pure, `apps/web/src/lib/console/class-code-overlay.ts`): the space is a `class`, `archivedAt` is null, `joinCode` is not null and `joinCodeExpiresAt` is later than `now`. `source` is `{ space: { name, kind, archivedAt }, joinCode, joinCodeExpiresAt }`, which both a `Roster` and a `SpaceListItem` satisfy (OD-CO7). An empty class shows it too: its page leads with the code already, but the overlay also hides the frame and the roster's empty state.
- No entry on a family roster, a school, an archived class, a class with no code or an expired one, or for a role that receives no code (§1.2). A class with no code keeps **Create a code** in Invite students, unchanged.

| Close | **Close** | `common.buttons.close` (shipped) |

- **Never in the overlay**: a learner's name, initials, avatar or level; any progress or summary value; the number of learners or seats; plans; the frame (tabs and their counts, Sign out, the attention banner); Copy, Regenerate or Create a code (no re-issue, WO-30); the join link as text (the QR carries it; Copy link stays in Invite students).

- **Opaque.** The overlay fills the viewport (`position: fixed; inset: 0`) with `colors.surface.paper`, with no scrim: no part of the page shows through, at any size or on any projector.
- **The browser's own chrome** (the tab strip with other tabs' titles, the address bar with the space id) stays visible unless the teacher uses the browser's full screen (F11, or the window's full-screen button); the overlay does not ask for full screen (OD-CO4, owner decision 2026-11-23).

### 3.3 Opening, closing, focus, the page behind, print

ConfirmSheet's focus rules (`AMENDMENTS-DISPLAY-NAV.md` §8), with the review sheet's first focus:

- `role="dialog"`, `aria-modal="true"`, named by the heading (`aria-labelledby`) and described by the caption, the spoken code and the expiry (`aria-describedby`, in that order). A screen reader hears: "Sunday Class A, dialog. Class code, S U N 2 3 4, expires in 18 days."
- Opening closes every open What to revisit body (§3.7), so the page is folded when the overlay closes.
- On open, focus goes to the heading (`tabIndex={-1}`), as the review sheet's title (`AttentionParts.tsx:247-255`): the content is to be read, and the one control comes next. Tab and Shift+Tab stay on Close (`tabTarget`, `ConfirmSheet.tsx`).
- **Escape** closes, caught for the whole document while the overlay is open. **Close** closes. There is no backdrop to click.
- While it is open every other element of the page is `inert` (`inertOthers`), undone when it closes, and the page does not scroll: the root element's `overflow` is hidden and restored on close, so no page scroll bar shows beside the overlay and the wheel over a short overlay does not move the page under it. While open, the root element also carries `data-hr-code-overlay` (removed on close), the hook of the print rule below.
- On close, focus goes to the opener **from its ref** (never from `document.activeElement` captured at open, §1.2). When the opener is no longer connected (`isConnected` false: the code ended or was replaced and the bar drew again), focus goes to the page head (`spaceHead`, `page.tsx:108`, drawn at `:486-487`); when the page head is gone too (a forbidden or gone read set the roster to `null`), to the error panel (`page.tsx:551-556`), which CO-1 gives `tabIndex={-1}` and a ref.
- **Print.** Printing while the overlay is open prints the overlay only: under `@media print`, `html[data-hr-code-overlay] [inert] { display: none }` removes the page behind (every element `inertOthers` marked), the overlay prints in the page flow (`position: static`) with `print-color-adjust: exact`, and Close is not printed. Without it, a print would drop the overlay's background and show the roster through it. A print of the class page itself is unchanged (no overlay, no rule).
- No address change, no history entry, no hash: the browser back leaves the page as it always has, and the overlay with it (the console has no history bridge, `AMENDMENTS-DISPLAY-NAV.md` §8).
- No motion: it appears and goes at once, so `prefers-reduced-motion` needs no branch.

### 3.4 Size on a phone, a laptop and a projector (tokens only)

The overlay sizes its type by the window, as the lecture presenter does (F-TCH-004 §3.6, the `presenter` tokens): one stage unit is `min(100vw / presenter.stage.width, 100dvh / presenter.stage.minHeight)` (1280 and 600; `vh` where `dvh` is missing). Each part has a console floor, so a phone never shows less than the console's own sizes.

| Part | Size | 1280 x 720 | 1920 x 1080 | 360 x 740 |
|---|---|---|---|---|
| Code | `max(typography.size.hero, presenter.size.display units)`, at most what fits six characters on one line of its column ("Fit") | 140 px | 210 px | 48 px |
| Space between the letters | `spacing.xl` for every `presenter.size.display` of code size (`spacing.xl / presenter.size.display` em, about 0.17 em), so it is `spacing.sm` at the floor | 24 px | 36 px | 8 px |
| Class name | `max(typography.size.title, presenter.size.prompt units)` | 56 px | 84 px | 28 px |
| Caption, expiry, how to join, QR caption | `max(typography.size.body, presenter.size.caption units)` | 28 px | 42 px | 18 px |
| QR side | `max(4 x touchTarget.min, presenter.size.glyph units)`, at most its column; in landscape at most the height left (below) | 380 px | 570 px | 256 px |
| Close | the console button, `touchTarget.min` tall | 64 px | 64 px | 64 px |

- **The code**: `typography.family.mono` (`'Menlo, Courier, monospace'`, `packages/design-system/src/tokens.ts:209`), `typography.weight.bold`, `colors.text.primary`, on one line (`white-space: nowrap`), never broken. It is drawn `aria-hidden`, with a visually hidden copy of its characters separated by spaces (`spokenCode`), so a screen reader reads it letter by letter (the presenter's rule, `EndSlide.tsx:172-175`). On Windows and ChromeOS the stack falls back to Courier New, whose bold is thin; the alphabet already leaves out I, O, 0 and 1 (§1.2), and the mock's Courier New render (`shots/class-code-overlay-1280x720-courier.png`) fits and reads; the owner checks it on such a projector (§3.9).
- **Fit**: the code's column is a size container; its font size is at most `100cqi / CODE_WIDTH_EM`, where `CODE_WIDTH_EM = 4.8` is six monospace characters at the 0.6 em advance of Menlo and Courier (3.6 em) plus seven letter spaces of about 0.17 em (1.2 em: six after the letters, and one before them so a centred code stays centred). Because the letter spacing is a share of the code size, the fit holds at every size.
- **Floors grow with the text size.** The floors are in rem (`typography.size.*` / 16), so the browser text size and the Display sheet's text size raise them; the stage sizes follow the window. Browser zoom shrinks the window in CSS px (1024 x 768 at 150 % is 683 x 512; 1280 x 720 at 200 % is 640 x 360), so a zoomed projector follows the rules of the smaller window.
- **Two columns** when the window is landscape and at least `layout.breakpoint.regular` (600 px) wide: the class name, the caption, the code, the expiry and the how-to-join line at the inline start; the QR with its caption centred under it at the inline end; both centred in the height; **Close at the bottom inline-end**, in reach on a wall-mounted touch panel. The QR is at most the height the window leaves: `100dvh` minus the two gutters, the Close row (`touchTarget.min`), three `spacing.sm` gaps and `QR_CAPTION_LINES` (3) lines of its caption. The switch is in px, not em: the overlay follows the window, like the presenter stage.
- **One column** otherwise, centred: **Close at the top inline-end** (it is last in the page order and drawn first), then the class name, the caption, the code, the expiry, the how-to-join line, the QR and its caption. The overlay scrolls (`overflow-y: auto`) when it does not fit (320 x 568 at 200 % text), never sideways; its body grows with its content, so centring never pushes anything above the top.
- **Space**: gutters `layout.gutter.compact` / `.regular` / `.wide` by the window class; gaps `spacing.*`, scaled by the stage unit like the type, with the console gap as the floor.
- **Colour**: `colors.text.primary` for the heading, the code and the QR modules; `colors.text.secondary` (8.4:1 on paper) for the caption, the expiry, the how-to-join line and the QR caption, never `text.muted`, because a projector washes contrast out. No `feedback.*` colour anywhere.
- On every landscape window the code and the whole QR are in the first screen, with no scrolling. Measured on the mock (`design/screens/console/class-code-overlay.md`, "Measured"): 1920 x 1080 code 210 px and QR 570 px; 1280 x 720 140 and 380; 1024 x 768 112 and 304; 683 x 512 69 and 256; 640 x 360 70 and 151; 360 x 740 48 and 256.

### 3.5 Reusing the QR

- The QR comes from the shipped code: `rosterJoinLink` makes the link and `qrModules` / `qrPath` / `qrViewSize` draw it (`join-link.ts:22-62`). Row CO-1 moves the `<svg>` of `JoinLinkQr` (`JoinLinkParts.tsx:76-88`, today numeric `width` and `height`, `maxWidth: '100%'`, `radii.md` and a `border.subtle` frame) into an exported `JoinLinkQrImage({ url, label, side, framed, testId })`: `side: number | string` (a number for the panel's `QR_SIDE`, a CSS length for the overlay), `framed: boolean` (the panel's radius and border), `testId` (the panel keeps `join-link-qr`, which `join-link.spec.ts` reads; the overlay uses `class-code-qr`). `JoinLinkQr` calls it with `QR_SIDE`, `framed: true` and its test id, so the roster panel draws exactly what it draws today and its tests do not change. No second QR library and no new drawing code.
- In the overlay the QR is always shown (no Show QR code toggle) and unframed: the paper around it is the quiet zone.

### 3.6 While the overlay is open

- **The new-device pop-up waits.** `useRelinkPopup`'s `blocked` (`page.tsx:247`) becomes `sheet !== null || confirmSheet !== null || codeOpen`, a second guard beside `otherModalOpen` (§1.2). A request that arrives while the code is shown opens its pop-up after Close. The banner and the card chips are under the overlay meanwhile, and a re-link closes in 10 minutes (`page.tsx:179-180`), so a request asked and closed while the overlay stayed up is missed; the learner asks again on the device. Accepted: the alternative is a learner's name on the classroom screen.
- **The code follows the roster.** Opening the overlay runs one quiet re-read (`load(true)`); while it is open the quiet re-read runs every `CLASS_RELINK_REFRESH_MS` (20 s, `visible-refresh.ts:22`) instead of every 90 s; Regenerate on the class page calls `announceRosterChange()` (`apps/web/src/lib/console/roster-broadcast.ts:56`), so another console tab of the same browser reads at once. A new code replaces the code and the QR in place; a code regenerated on another device shows within 20 s (the old one stops working at once, F-SPACE-001 §3.2). `now` is taken at each render (`page.tsx:98`), so the expiry words follow the re-reads. When the source no longer has a live code (`codeOverlayShown` turns false) or the roster goes (forbidden, gone), the overlay closes, with the focus fallback of §3.3.
- **The grown-up lock.** A cover (the hidden tab, the re-check) sits above the overlay (`GrownUpLock.tsx:428-437`, the highest `z` token) and shows no learner data. A lock (§1.2) unmounts the page, overlay included. So that the unlock does not put the roster on the classroom screen, the page keeps a session flag while the overlay is open: `hr:console:codeOverlay` = the space id only, through `apps/web/src/lib/i18n/safe-storage.ts` (`browserStorage('session')`); Close, Escape and a self-close remove it. When the class page mounts with the flag naming its space, it opens the overlay in the same render that first draws the roster (the `#attention` pattern, `page.tsx:235`), so the roster is never painted, and removes the flag if there is no live code. When the page unmounts and the address no longer names this class (a navigation, not a lock), it removes the flag. The overlay uses `z.modal`.
- **Offline**: the overlay draws from the roster in memory and the QR in the page, so it works offline.

### 3.7 The roster card: what to revisit starts folded (row CO-2)

- On a **class** roster, a card with a summary shows at line 4 (GX-7 T4) a disclosure button **What to revisit** (`console.space.learner.revisitToggle`) with the console chevron (`ClassPageParts.tsx:22-35`): `aria-expanded`, `aria-controls` only while open, `aria-describedby` the learner's name (`roster-learner-{index}`, as Send a note does, `page.tsx:729`), at least `touchTarget.min` tall. It starts **closed** on every page load.
- Open, its body shows the card's "Revisit: ㅂ · ㅅ" line (the text and `lang="ko"` of `page.tsx:685-691`, unchanged) and the "Words to revisit: …" line (`VocabWordsParts.tsx:69-75`, romanization and gloss unchanged; OD-CO1, owner decision 2026-11-23). A card with neither shows **Nothing to revisit yet.** (`console.space.learner.revisitNothing`).
