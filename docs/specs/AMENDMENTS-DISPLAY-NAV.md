## 3. One display record per device (amends F-I18N-001 §3.2 and §3.3)

### 3.1 The record

```ts
// packages/content-schema/src/schemas/locale.ts (additive; 100 % covered) — as built in DN-1 (#731)
export const TEXT_SIZES = ['standard', 'large', 'larger', 'largest'] as const;
export const TextSizeSchema = z.enum(TEXT_SIZES);
// The factors live with the type scale: @hangul-route/design-system `TEXT_SIZE_FACTORS` (text-size.ts), section 4.
export const MIGRATED_AT = '1970-01-01T00:00:00.000Z';   // the time of a migrated or seeded language: older than any real choice
// Every field reads an unknown or bad value as absent (the ProfileSettingsSchema rule), so a value written by a
// newer build (another console deploy, a rollback) never fails the whole record and loses the other fields.
export const DeviceSettingsSchema = z.object({
  uiLocale: UiLocaleSchema.optional().catch(undefined),                              // absent = never chosen on this device
  uiLocaleAt: z.string().datetime({ offset: true }).optional().catch(undefined),     // ISO time of the choice; absent counts as MIGRATED_AT
  textSize: TextSizeSchema.optional().catch(undefined),                              // absent = 'standard'
});
export const DEVICE_SETTINGS_KEY = 'device:settings';   // stored as hr:device:settings (the existing key)
export function mergeDeviceSettings(raw: unknown, patch: { uiLocale?; uiLocaleAt?; textSize?; clearLocale?: true }): Record<string, unknown>;   // read-modify-write: keeps unknown keys
export const PREFS_CHANNEL = 'hr-prefs';
export const PrefsMessageSchema = z.object({ ns: z.literal('hr-prefs'), v: z.literal(1), type: z.literal('device-settings'), settings: DeviceSettingsSchema }).strict();
export const AccountLocaleSchema = z.object({ uiLocale, uiLocaleAt });   // Clerk unsafeMetadata, lenient (section 5)
export function mergeAccountLocale(device: DeviceSettings, account: AccountLocale | null): { device: Choice | null; account: Choice | null };   // newer wins; a missing time is MIGRATED_AT; a tie keeps each side
```

Built differently from the DN-0 draft (#731, recorded here so the later rows read the code as it is): the time is an ISO string (as the row asked), with `MIGRATED_AT` (1970) where the draft had `0`; `newerChoice` is `mergeAccountLocale`, which returns what each side must write; `resolveUiLocale` stays in the stores (`locale-store.activeLocale`, `console-locale.resolveConsoleDisplay`), which each add their own sources; the step factors are the design system's.
- **Where it lives.** The existing learner key `hr:device:settings` (JSON string in the default idb-keyval store, `platform/storage.web.ts`). The learner app, All lessons and the presenter use `readJson` / `writeJson('device:settings', …)`; the console uses a reader and writer in `lib/i18n/device-settings.ts` built like `device-marker.ts` (guarded, a read or a write retried once on a fresh connection, `null` on failure). A failed or blocked storage means "never chosen" and the choice lasts for the page only, as today (F-I18N-001 §3.2 last Given).
- **Who writes.** Only the **Display** sheet (section 3.6), Welcome's language chips (first run, F-I18N-001 §3.3, unchanged otherwise), the `?lang=` seed (section 3.4), the migration (section 3.3) and the account merge (section 5). A choice on the sheet or on Welcome writes `uiLocale` with `uiLocaleAt` = the time of the choice; the seed and the migration write `uiLocaleAt: MIGRATED_AT`; a text size writes `textSize` alone. Detection writes nothing.
- **How it is written (every writer: learner app, All lessons, presenter, console, account merge).** Read the raw stored object, change only the named fields and write the whole object back (`mergeDeviceSettings`), so a field another build added (`textSize` for a build that predates it, or a later field) survives. The record is **never removed** (`removeKey` is not used on it): clearing the language deletes `uiLocale` and `uiLocaleAt` only. A record `uiLocale` without `uiLocaleAt` (a record written before DN-3, or by a cached older build that still writes `{ uiLocale }`) counts as `MIGRATED_AT`. Such an older build overwrites the whole record when it changes the language, so its text size returns to Standard until chosen again; the language is kept, and a cached build is replaced at its next update (the update banner). Not worth more machinery (section 15).
- **Removed.** `ProfileSettingsSchema.uiLocale` (the per-profile override; `romanizationMode` stays, per profile, as F-I18N-001 D2 wants), `locale-store.setProfileLocale`, the Profile Language card's "This profile" part, F-BROWSE-001's `setSessionLocale` and the browse Language chips, the presenter's session chips (`AMENDMENTS-LECTURE-V2.md` section 18.4). The console's `hr:console:uiLocale` stays as a read-through mirror of the record's language (section 3.3).

### 3.2 Resolution and who reads it

`activeLocale = resolveUiLocale({ device: record.uiLocale, account: signedInAccount?.uiLocale, detected, available })`: the first of device record, account, detection that the build offers; else `en`. The learner app has no account (learners never sign in), so there it is device > detection > `en`; the console adds the account. Placement's test-language default (F-PLC-001 §3.1 step 2: "profile override, else device, else detected") becomes the resolved locale; the test language stays a run-only choice (DN-D8).

### 3.3 Migration (once per device, idempotent, no marker)

The migration keeps what each person sees today: the language on screen before the update is the language after it. It is split by owner, because the learner app (DN-3) and the console (DN-5) are separate builds that deploy at different times.

**Learner app (DN-3)**, on each boot inside `hydrate`, before the first render (`hydrateLearnerData`):
1. If the **active profile** (with no active profile, the only one) has an override (`hr:settings:<activeProfileId>.uiLocale`), write it to the record with `uiLocaleAt: MIGRATED_AT`, whatever the record held (an equal language keeps the record's own time): it is the language that profile sees today (the shipped resolution is profile override > device > detection, `store/locale-store.ts`). Else the record stays as it is. A record that cannot be read (a failed read, not a missing key) skips the migration for that boot.
2. Only once that write is stored, remove `uiLocale` from every `hr:settings:<profileId>` (keep `romanizationMode` and every other field), so a failed write loses nothing. **The learner app never reads or removes `hr:console:uiLocale`.**
3. An override on a profile that is not active is dropped, not folded: one language per device (the owner's request), and the active profile's view decides.

**Console (DN-5)**, after its record read settles, before its first locale switch: on a device **with no learner profiles** (`hasProfileList` false, a teacher laptop that never ran the learner app), if the record has no `uiLocale` and `hr:console:uiLocale` holds a locale, write it to the record with `uiLocaleAt: MIGRATED_AT` (before any `?lang=` seed). `hr:console:uiLocale` is **kept as a read-through mirror** of the record's language (written when the record holds one, cleared when it holds none), for the first paint and for a browser whose IndexedDB cannot be read. The console never reads or writes `hr:settings:*`; besides the record and its own keys it reads only what `lib/console/device-marker.ts` already reads (the gate marker and whether `hr:profiles` is a non-empty list), and it never parses profile data.

As built (#731), against the DN-0 draft: the learner app does not fold `hr:console:uiLocale`, and the console folds it only on a device with no learner profiles and keeps it as a mirror. The learner app and the console ship in one app-host build (F-APP-001 A-3, `merge-console.mjs`), so there is no window in which a new learner app runs next to an old console; and on a device where the learner app runs, its language (chosen, or detected and handed off as `?lang=`) is the one the learner sees, so an old console choice must not switch the learner app.

Because step 2 removes what step 1 reads, a second learner boot finds nothing to do; no version field is needed. A cached older learner build that writes a profile override again after the migration has it folded again at the next DN-3 boot (it was the latest choice on screen). Tested with corrupt values, a blocked store, a failed device read, a failed promotion write, a record that differs from the active override, an override on an inactive profile only, an override written again by an older build, and the console key on a device with and without learner profiles (section 13).

### 3.4 `?lang=` (amends F-I18N-001 §3.3 "Web hand-off" and `pickConsoleLocale`)

- **The record is read first.** The learner app takes the parameter inside `hydrate`, after the record read and before its first render (as it does today); the console takes it after its record read settles (one read and its retry), before its first locale switch, and its static HTML stays English until then (as it is today until mount). So a stale or outside link never paints over a choice, not even for one frame.
- A valid `?lang=` for an offered locale then **seeds** a device that never chose: if the record has no `uiLocale`, it is written with **`uiLocaleAt: MIGRATED_AT`** (a seed, like a migrated value, never beats a choice from the account, section 5); otherwise it is ignored. Either way it is removed from the address with `history.replaceState`. The same holds for an All lessons pass's `uiLocale`.
- `pickConsoleLocale`'s order "`?lang=` first and store it" (F-APP-001 §3.7 last bullet) becomes: record > account > `?lang=` seed > browser.

### 3.5 Open tabs stay in step

A write posts `PrefsMessageSchema` on `BroadcastChannel('hr-prefs')` (feature-detected; absent = no sync, the next boot reads the record; a page also re-reads the record on `visibilitychange` and `pageshow`). Each tab posts and listens on **one** channel instance, so it never receives its own writes. Every root listens: the learner app, All lessons, the presenter and the console apply the settings at once (language and text size), without a reload, and without writing. A tab with a running lesson or quest applies them too (only words and sizes change; no state is lost). The channel is separate from F-TCH-004's `hr-tabs` presence ping.

### 3.6 The Display control and sheet

Wireframe `shell/display-sheet.md`; mock `design/screens/app-shell/display-sheet.md`.

## 4. Text size (amends F-LAYOUT-001 LD4)

- **Factor** `f = TEXT_SIZE_FACTORS[record.textSize ?? 'standard']` (`@hangul-route/design-system/text-size`). **Body sizes** (`caption`, `bodySm`, `body`, `bodyLg`, `prompt`) are `round(token x f)`; **heading sizes** (`title`, `display`, `hero`) are `round(token x (1 + (f - 1) / 2))`. Largest: body 18 -> 27, prompt 22 -> 33, title 28 -> 35, display 36 -> 45, hero 48 -> 60. `leading.*` stays a ratio, so line heights follow.
- **Learner app and All lessons** (RN): `TextSizeProvider` (design-system) gives `useTypeScale()` the scaled sizes; React Native then applies the OS text size on top (`allowFontScaling`), so the effective scale is `fontScale x f` (`useEffectiveFontScale()`, which the layouts that switch on a larger text read), and a native `maxFontSizeMultiplier` cap is a budget for both (`useCappedFont`). Screens and components read sizes only from `useTypeScale()` or a design-system text component; a source scan (`apps/mobile/src/logic/__tests__/type-scale-scan.test.ts`) counts every raw `typography.size.` under `apps/mobile/src/screens`, `src/components` and `packages/design-system/src/components` and holds each file to its listed count, so the list only shrinks. DN-3 (#731) moved the shared components, the four tab roots, the quest player, every minigame and the presenter's controls and overlays; what stays by design is the stage, media (card art, stroke diagrams, covers, badges, syllable diagrams), the Journey grid's fixed cells and the on-screen Hangul keyboard; the `DN-3b` entries reached zero in DN-3b (#733), and the scan now also holds the whole list to at most 31 uses, with a screen keeping an entry only for a picture.
- **Console** (DOM, rem): the root sets `--hr-text-scale: f` and `--hr-head-ratio: (1 + (f - 1) / 2) / f` on `html`, and `html { font-size: calc(100% * var(--hr-text-scale)) }`; heading classes are `calc(<token rem> * var(--hr-head-ratio))`. The browser's own text size still multiplies all of it.
- **Presenter**: its teacher pages (home, start screen, state pages, the overlays' real-pixel controls) follow `f`; the **stage keeps stage units** (F-TCH-004 §3.6), because a projected slide is sized for the room, not for the person holding the device.
- **What does not scale**: touch target minimums (`touchTarget.*`) stay; controls grow with their text, never shrink. Media (`mediaScale`) is unchanged.
- **Fit rule.** At 320 x 568 with **Largest** and the OS text size at 100 %, no learner screen scrolls sideways and no text is clipped (Playwright on the four tabs, Profile, Grown-up area, a quest step of each minigame family, the Display sheet). Fixed-height rows become `minHeight`. As built (DN-3b, #733, after its review): "clipped" is measured, not only looked at: a line of text partly cut by a box that hides its overflow fails (a deliberate `numberOfLines` clamp and a pager's other pages do not), and a text field holding a value scrolls neither sideways nor down (`e2e/web/text-fit.ts` `expectTextFits`, used by `text-size-fit.spec.ts` and the 320 x 568 cases of `one-language.spec.ts`). `text-size-fit.spec.ts` covers a game of each of the four families (Match Sound; Build a Letter and Trace; Tap & Respond; the Culture Quiz), Stage complete's letter wall, Join a class with the widest code, and the Rescue Code fields of Restore and Forgot PIN with a code pasted with its hyphens. What the measure found is fixed in the same row: a class code field (Join a class, Move to another class) draws the code at the display size but never larger than lets six of the widest letter fit the field (`codeFieldFontSize`); the letter wall's tiles grow with the text size and share each row's width (`wallTileWidth`), so `silent/ng` stays inside its tile; and a Rescue Code field plans one row per word or number whether a space or a hyphen joins them (`rescueInputRows`). **The console too**: at 320 wide with Largest and the browser text size at 200 % (a 300 % root), the AdultFrame header, a PageBack page (plan, settings, lecture) and the Display sheet do not scroll sideways; header rows wrap (the Learner app exit wraps its label and the tools wrap when the row is full; content buttons and the text-size rows break a long word) instead of holding one line (`page-back.spec.ts`, section 13).

### 7.2 The web history bridge (amends F-LEARN-001 §3.15.4)

F-LEARN-001 §3.15.4 says the browser back reaches the `beforeRemove` listener "only once the web build has a linking config". That line is amended: the learner web build gets a **history bridge** (`platform/history-bridge.web.ts`; the native stub does nothing) for `App` and `BrowseApp`, without a URL scheme (LD7 of F-LAYOUT-001 still holds: no deep links; the address never changes). The bridge is a **reconciler**: it keeps the tab's history entries in step with the navigator's state, whoever changed it.

- **Depth.** The app's depth is the number of routes above the root along the focused path of the nested stacks (a sheet or modal that is open counts one more). Each entry the bridge owns carries its depth as `hrNav` in `history.state`, merged with the other keys of the same entry: All lessons keeps its own `hrBrowseDepth` (F-BROWSE-001 BD1, `platform/browse-env.web.ts`), and every `pushState` / `replaceState`, the bridge's and `browse-env`'s (`stripAddress` included), reads the entry's state object and writes it back with both keys.
- **Boot.** The entry the app opens on becomes `hrNav: 0`. If it already carries `hrNav > 0` (a reload deep in the app: the navigator restarts at its root), the bridge first rewinds with `history.go(-hrNav)` and ignores the popstates it causes, so no dead entry is left behind and the next back leaves the app in one press. A boot stack deeper than the root (All lessons' entry stacks, `logic/browse/boot.ts` `entryStack`) pushes one entry per route above it.
- **The app changed the stack** (a push, the visible Back, `replace`, `reset`, `pop`, `popToTop`, a sheet closed by its own button): on every navigator state change the bridge compares the depth with the current entry's `hrNav`. Deeper: one `pushState` per added level. Shallower: `history.go(-(hrNav - depth))`, marked as its own so the popstate it causes is ignored. The same depth (`replace`, a `reset` to the same depth such as a quest's `[Main, Results]` or CreateProfile's replace): nothing, because an entry stands for a depth, not a route.
- **The browser changed the history** (a popstate the bridge did not cause): a target `hrNav` **below** the depth pops `depth - target` levels through the `beforeRemove` guards, one level at a time (a long-press jump of two entries runs both guards); when a guard cancels (a quest's leave sheet), the bridge pushes the entries the browser took away back, so the history matches the screen still shown. A target **above** the depth (Forward, or an iOS swipe forward) is **never replayed**: the bridge goes straight back with `history.go(-(target - depth))`, so Forward never reopens a screen the person left, a gated one (the Grown-up area) included.
- **Sheets** (ConfirmSheet, the Display sheet) are one level while open: opening pushes; Done, Cancel, `Esc` or the backdrop goes back one entry (marked as its own); the browser back closes them as Cancel does.
- **All lessons.** `BrowseApp`'s Close goes back `1 + hrBrowseDepth + hrNav` (past its later links and its stack entries) and `canGoBack` counts both, so Close from two items deep still lands on the console page that opened All lessons in this tab (F-BROWSE-001 BD1 kept).
- At the root the browser's own back leaves the app, as today.
- **Leaving the page.** A hand-off that loads another page in the same tab (the PIN's way to the grown-up pages, Account pages, Open billing, All lessons, a persona's sign-in, All lessons' own way back to its opener) starts with `location.assign` (or a `history.go` to another document), and a `history.go` from the reconciler in the same task would cancel that navigation. So every such hand-off marks the tab as leaving itself, right before it leaves (`markLeaving()`; iOS Safari and an installed iOS app do not fire `beforeunload` reliably, and a source scan holds every `location.assign` of the platform files to it), and `beforeunload` and `pagehide` mark it too; while it is marked the bridge writes no history. No timer clears the mark (a slow page on a phone network is still leaving after any fixed wait): `pageshow` (the page shown again from the back-forward cache) clears it and reconciles once, and so does the person using the page again (a tap or a key) at least 10 s after the mark, with the tab visible, which means the navigation did not happen.

## 11. Privacy, child safety, accessibility, offline, telemetry

- **Privacy.** The record holds a locale code, a timestamp and a size code: no name, no profile id. The account copy holds the same two fields in Clerk's `unsafeMetadata` (the user can write it; nothing trusts it beyond display). The `hr-prefs` message carries the same record. Nothing leaves the device except that Clerk write.
- **Child safety.** The Display sheet is not gated: changing the language or text size touches no data and is reversible in the same place (F-I18N-001 L7). The Grown-up area keeps its gate; the Profile split moves no gated action out from behind the gate (Weekly plan's child path still asks, Backup still asks), and it puts one more behind it: **Leave a class or a family** (section 9.2; Join stays open through **Got a class code?**, the same Join screen a learner can open today). The history bridge never replays a browser Forward (section 7.2), so a gated screen the person left never comes back without the gate.
- **Accessibility.** `ScreenHeader`'s Back is the first focus stop; the Display sheet's radios are native groups with legends; the preview line is read as plain text; ConfirmSheet traps focus and returns it; every control at least `touchTarget.min`; Largest text at 320 px scrolls nowhere sideways (section 4). Language radios carry `lang`.
- **Offline.** All of it works offline: the record is local, the Clerk merge waits for the next online load.
- **Telemetry.** No new event and no new key. The shipped **`locale.changed`** (`{ from, to, scope, source }`, F-I18N-001 line 352, `TELEMETRY_EVENT_NAMES`) **stays, for language only**: the learner app emits it from its Display sheet (`source: 'settings'`), from Welcome's chips (`'welcome'`) and from the `?lang=` seed (`'handoff'`), always with **`scope: 'device'`** and no `profileId`. `scope: 'profile'` is no longer sent (the Worker keeps accepting it for older clients; the exact-list test is unchanged). No new `source` value: the migration, the account merge and a broadcast from another tab emit nothing, and All lessons, the presenter and the console emit nothing for display choices (the console has no telemetry client; the presenter sends lecture events only). A text size, a Back press and a confirm send nothing.
